# Theme reference

Put these keys in `[theme]` in `$XDG_CONFIG_HOME/rediwm/config.toml`.
`REDIWM_CONFIG` selects another config file; `REDIWM_THEME` overlays another
file's `[theme]` section. Omitted keys use the built-in defaults below.
Appearance saves custom tokens along with its sliders and selectors.
The bundled picker includes RediWM Dark, RediWM Light, Redi Blue and Redi-Mocha.
Redi Blue uses navy surfaces, cyan accents, 98% chrome opacity and a 30% selection tint.
RediWM Light uses 75% window chrome opacity and teal selection accents.
Redi-Mocha uses the [Catppuccin Mocha palette](https://catppuccin.com/palette/#mocha),
mauve accents and the bundled `wallpaper-mocha.png` Auckland skyline.
`start_button_logo_color` optionally tints the bundled R logo; Light uses a
dark tint for contrast. Custom start-button icons retain their own colours.

Appearance also has a **Taskbar theme** picker under Theme, with the same
presets plus "Same as theme". It gives the taskbar the preset's colours and
leaves every other surface on the theme above. It is saved as a
`[taskbar_theme]` section holding only these keys: `clock_bold`, `clock_italic`, `taskbar_bg`,
`taskbar_surface`, `taskbar_hover`, `taskbar_border`, `taskbar_outline`, `border_soft`,
`surface_hover`, `window_fg`, `window_dim`, `danger`, `window_close_hover`,
`start_button_hover`, `start_button_indicator`, `start_button_logo_color` and
the `battery_*` colours. Unlisted keys are ignored, so a whole theme file's
body can be pasted under that header; keys it leaves out take the built-in
defaults, not the main theme's. The section's presence selects the taskbar
theme (an empty one is the built-in colours); without it the taskbar follows
`[theme]`. Sizes, gaps and radii always come from `[theme]`.
Under **Appearance → Taskbar**, **Bold clock text** and **Italic clock text**
independently style both time and date. They save into the selected taskbar
theme, or the main theme when the taskbar follows it. Both default to false;
Gold uses bold with italics off. Clock widths and digit spacing update live.

## GTK and Qt app colors

In **Settings → Appearance**, **Apply GTK colors** and **Apply Qt colors**
sit below the Theme and Taskbar theme selectors. They export the current
main theme's app backgrounds, toolbar, sidebar, text and shell accent.
The taskbar override does not affect app colors. Exports are snapshots:
apply again after selecting or editing a theme, then restart the apps.

GTK colors are written to `gtk-3.0/rediwm-colors.css` and
`gtk-4.0/rediwm-colors.css` under `$XDG_CONFIG_HOME` (otherwise `~/.config`).
A marked import is added at the *end* of each `gtk.css`, so it wins over palettes
imported there by other generators (matugen, DMS) while the rest of the file is
preserved. Applying again moves an older block that sits first. GTK3 includes common widget color overrides; GTK4 also
gets the CSS variables used by recent libadwaita. No theme package is patched
and the dark-mode preference is never briefly flipped to force a refresh.

Qt colors require **qt5ct** for Qt 5 apps and **qt6ct** for Qt 6 apps. The
installed toolkit configurations select native `colors/rediwm.conf` palettes
and the palette-aware Fusion style. Other preferences are preserved.
RediWM launches receive the selected platform theme and style immediately;
sign in again to update the environment for apps activated by D-Bus or
launched elsewhere. This opt-in is recorded in `rediwm/app-colors.conf`.
KDE apps such as Dolphin read `kdeglobals` rather than the qt6ct palette, so
the Qt export also rewrites the `[Colors:*]` groups there (Window, View,
Button, Selection, Tooltip, Complementary, Header). Other keys are kept, and
the first copy is saved as `kdeglobals.rediwm-backup`. The file is shared with
any Plasma session, which will see the same palette.
Bundled Qt runtimes, sandboxed apps, and apps with their own styles may need
their own configuration.

The first existing user configuration is backed up beside its original as
`<filename>.rediwm-backup`; later applications keep that first backup.
A `gtk.css` (or Qt config) that is a symlink, for example one generated by
another theming tool, is replaced by a regular file holding its current
contents plus the RediWM block; the link target is not modified. A config
*folder* that is a symlink is refused and reported in Settings. To undo GTK colors,
remove the marked RediWM import blocks from both `gtk.css` files (or restore
their backups). To undo Qt colors, restore the qt5ct/qt6ct configuration
and `kdeglobals` backups (or delete configurations created by the export if no backup exists),
remove `rediwm/app-colors.conf`, and sign in again.

## Color tokens

Colors accept `"#rrggbb"`, `"#rrggbbaa"`, or `"rgba(r,g,b,a)"` with RGB
channels from 0 to 255 and alpha from 0 to 1. Numbers must be finite and
nonnegative. Sizes are logical pixels. The tables describe appearance tokens;
window placement, animation timing, cursor themes and sizes, blur, inactive
opacity and frame radius also have settings in the other config sections.

```toml
[theme]
shell_accent = "#86bfff"
control_thumb = "#ffffff"
toggle_track = "rgba(120,140,170,0.25)"
slider_track_height = 6
app_text_size = 14
app_heading_size = 13
app_status_size = 12
desktop_selection = "rgba(80,140,220,0.2)"
desktop_selection_border = "#508cdc"
battery_full = "#40dca0"
image_checker_size = 16
pdf_search_match = "rgba(100,180,255,0.4)"
```

## Palettes and reload

Shell surfaces use `window_fg` and `window_dim`. Their accent normally follows
`start_menu_selected_marker`; `shell_accent`, `shell_on_accent` and
`shell_border_focus` override that palette and its control/field focus rings. Settings uses `settings_radius` for
controls. Text fields, carets and text selection have optional overrides that
otherwise follow the accent of the surface displaying them.

Files' New, Sort and Filter buttons share the secondary-button palette:
`surface` sets the background, `surface_hover` the hover fill, and `border_soft`
the border. Their text and icons use `window_fg`. Active Filter and view-mode
buttons use `shell_accent` (or `start_menu_selected_marker` when unset), tinted
by `button_selected_alpha`. All of these values can be set in `[theme]`;
Files follows edits while running.

Files' dialog bodies and context menus share `app_toolbar` as their background
color. Changing it in `[theme]` updates both.

The compositor reloads the theme when the config changes. Files and Images
follow saved colors and sizes; PDF and Editor load them when starting. The
compositor's frame radius is the numeric `[theme].radius_lg`. The legacy
`[compositor].border_radius` is used only when the theme omits `radius_lg`.
Appearance's Radius presets write all numeric radius tokens: Default restores
the current built-in radii, Sharp caps them at 4 px (the minimap's default),
and Round uses 1.3 times the defaults. Individual theme radii remain editable.
Cursor styling is `[input].cursor_theme` and `[input].cursor_size`; animation behavior belongs in `[animations]`.

Set `[theme].chrome_round_buttons = true` for circular window controls and
pill-shaped window tabs. Tab close, new-tab and overflow controls follow the
same setting. It defaults to `false`, preserving the existing corner radii,
and reloads live from the main config or the `REDIWM_THEME` file. Button sizes
and hit targets stay the same; `radius_lg` still controls the window frame.

`[theme].window_shape` replaces the rounded rectangle of server-decorated
windows with a polygon: up to 16 points, `"x y"` pairs separated by commas.
A coordinate is logical px from the left or top edge, a negative one (`-0`
included) px from the right or bottom edge, and `N%` a fraction of the window,
so one outline fits any size. For example
`window_shape = "0 14, 14 0, -160 0, -148 3, -14 3, -0 17, -0 -14, -14 -0, 14 -0, 0 -14"`
cuts the corners and steps the top edge down for its last 160 px. The ring,
shadow, glass and pointer picking follow the outline. An outline that does not
parse is refused when the theme loads; one that crosses itself at a window's
size (a window narrower than its notches) falls back to the rounded rectangle,
as do maximized and fullscreen windows. `window_top_band` (colour) and
`window_top_band_height` (logical px, 0 = none) paint a strip along the top of
the titlebar, clipped by the shape. The titlebar's icon, title and controls
(and the tab strip's right end) keep in from the outline's slanted or cut ends
over the rows they occupy; a notch they do not reach into is left to the clip.
The outline's GL programs are built the first time a theme asks for one, so a
theme without `window_shape` or `taskbar_shape` never pays for them. The
`chamfer-blue` pack (`assets/themes/chamfer-blue.toml`, not yet offered in the picker) is an example.

`[theme].taskbar_shape` does the same for the taskbar, against the bar's own
box (so `-0` is the bar's right or bottom edge): for example
`"0 -0, 14 0, 300 0, 312 6, -14 6, -0 -0"` is a raised left section, a 6 px step
down and a slanted right tip. It replaces `taskbar_radius`. Items keep clear of
the slanted ends but not of a notch in the middle, the notch is transparent and
clicks in it reach what is below, and glass follows the outline. The bar is
painted once per layout change, not per frame.

The lock's background always paints opaque, even if `lock_bg` supplies alpha;
`lock_wallpaper_opacity` controls its wallpaper overlay. Actual image pixels,
PDF paper/content, application-provided icons and fixed layout/hit-test
geometry retain their content or structural dimensions.

### Component relief

When `relief_depth` is greater than zero, individual controls can opt into
`"flat"`, `"raised"`, or `"inset"` relief. Flat is the default for components
that did not previously use explicit relief. The standard slider progress fill
overlays the start of the track, so an inset `slider_track_relief` can have its
left-side groove shadow covered by that fill. The shaded slider and toggle paths
(`slider_shaded`, `toggle_shaded`) keep their procedural lighting and add these
shadows on top, dropping only what the relief would double: the toggle's hand-made
track rim under a non-flat track relief, and the knob's cast shadow under a
non-flat thumb relief. A groove's shadows skip its knob, and a knob's stay inside
its track (toggle) or the slider's box, so neither crosses the thumb or outlives
the control's damage bounds. A theme that leaves the keys `flat` renders exactly
as before. Raised shadows reach `relief_depth + relief_softness` past a box: use
`inset` for segments, rows and pills packed into a layout.

`taskbar_height` is an alias for `taskbar_size`. The taskbar is a flush,
full-width, square bar by default. `taskbar_edge_gap` (0–64 logical px, in
Appearance as **Taskbar gap from edge**) floats it off the screen edge it sits
on, `taskbar_length` (a percentage of that edge, centred; never narrower than
its items need, 420 px) shortens it, and `taskbar_radius` (px; a pill at half
the bar's height) rounds its corners. Windows and panels treat the bar and its
gap as reserved space. `taskbar_outline_width` is the thickness of the bar's own
outline and the optional colour `taskbar_outline` its colour (unset: `border_soft`,
which drew the bar's single hairline before). A flush bar draws the outline on the
side facing the windows only; a floating or rounded one draws it all round.
`taskbar_border` stays the colour of the window buttons' and battery's outlines.
The Radius presets (Sharp, Default, Round) leave `taskbar_radius` alone. Layouts cap some dimensions to
fit their available space. The scrollbar reserves room for its maximum width;
`slider_*` keys control slider geometry while sharing the scrollbar feedback.

In **Settings → Appearance → Start menu**, **Choose file…** selects a PNG or
SVG for the Start button logo and applies it immediately. **Reset to default**
restores the bundled R logo. Both choices are saved with the theme. A preview
beside the buttons shows the logo as the taskbar draws it (the bundled R when a
chosen file cannot be loaded). The **Menu width** (400–900) and **Menu height**
(360–900) sliders in the same section set `start_menu_width` and
`start_menu_max_height`; the menu is still capped to the output. Left at `0`
(the default) the menu is sized to the screen: 560 x 600 on a screen of about
1700 x 1070 logical pixels or more, and the same share of the screen (33% wide,
56% high) on smaller ones, never below 400 x 360. **Size to screen** returns to
that.
